3.1　三个约束回答三个不同问题

容量回答状态能否放下；带宽回答数据单位时间能搬多少；算力回答单位时间能做多少规定精度的运算。一个任务先要满足容量可行性，再分析时间。H20、910C 的型号名不能代替 SKU、精度、设备可见内存和互联事实。

3.2　算术强度与双下界

定义本次操作的浮点运算数 F，单位 FLOP；实际经过选定存储边界的流量 D，单位 byte。算术强度 I=F/D，单位 FLOP/byte。选择的边界通常是 HBM 与片上存储；若分析网络，D 改为通信流量，两种强度不能混用。

I = F / D [FLOP/byte](3.1)
t ≥ max(F / C_eff, D / B_eff)(3.2)
P ≤ min(C_eff, B_eff × I)(3.3)

C_eff 与 B_eff 是针对当前 dtype、shape、设备和访问方式能够达到的计算率与带宽。用厂商峰值绘制 Roofline（屋顶线）是理想上界；实际能力通常更低。式 3.2 忽略 CPU 提交、通信依赖、索引、同步和串行工作，不能当作精确总耗时公式。若计算和数据搬运重叠不足，总时间也可能接近两者之和。

例题 3.1　一个教学 GEMM 在哪一侧

已知 Y=XW，X=[32,4096]，W=[4096,4096]，输出 [32,4096]，全部 2 byte；乘加按 2 FLOP 计。假设输入、权重各从 HBM 读一次，输出写一次。

F = 2 × 32 × 4096 × 4096 = 1,073,741,824 FLOP
D = 2 × (32×4096 + 4096×4096 + 32×4096)
  = 34,078,720 byte = 32.5 MiB
I ≈ 31.51 FLOP/byte
教学 C_eff=100 TFLOP/s，B_eff=1 TB/s（十进制）
t_compute≈10.74 μs；t_memory≈34.08 μs
理论双下界≈34.08 μs

这里使用人为给定的有效能力，不是 H20 或 910C 数据。若 T 从 32 变为 1，权重载荷仍大，I 约为 1 FLOP/byte。更大的 batch 增加复用潜力；是否真的发生取决于 kernel、缓存与布局。

3.3　把“可能受限”变成实验

先明确流量估算：权重被多次读取、KV 访问、临时分数矩阵、量化解包和 cache 命中都可能使 D 与最小元素数不同。对标准 Decode，长上下文的 K/V 读取随历史长度增加；索引/稀疏/压缩模型需要重新逐项计数。

如果认为权重带宽受限，固定模型和长度扫描 batch，并观察 kernel 时长、访存指标与提交间隙。如果认为启动开销受限，比较同工作量在不同调用组织或 eager/graph 下的行为，先保持正确性。只凭设备利用率、吞吐增加或一个峰值百分比不足以归因。

检查：模型因 OOM 无法启动，增加算力能解决吗？

不能直接解决。容量由驻留权重、KV/状态、workspace 和运行时资源决定；只有同时改变可见容量、分片、精度或驻留策略才可能影响可行性。
