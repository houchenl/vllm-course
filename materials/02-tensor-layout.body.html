2.1　shape 告诉你有什么，stride 告诉你怎样找到它

同一个数学矩阵可以有多种存储布局。shape 是各维元素个数；stride 是某维索引增加 1 时，存储偏移增加的元素数。dtype 的 element_size 再把元素偏移转换为字节偏移。因此，形状相同不保证 kernel 接收到同样的访存模式。

offset(i₀,…,iₖ) = storage_offset + Σⱼ iⱼ × strideⱼ(2.1)

式中 offset 与 stride 的单位都是元素，索引必须落在 shape 内；地址相对存储起点的字节偏移为 offset×element_size。这里讨论普通 strided dense tensor，不把稀疏格式或专用量化打包套进同一地址规则。

例题 2.1　转置后为何没有重新排列存储

已知连续矩阵 X=[[0,1,2],[3,4,5]]，shape=(2,3)，stride=(3,1)。X[1,2] 的元素偏移为 1×3+2×1=5。令 Y=X.transpose(0,1)，则 shape=(3,2)、stride=(1,3)；Y[2,1] 的偏移也是 2×1+1×3=5。转置改变访问规则，仍访问同一元素。

若 Y.contiguous() 产生新连续布局，结果矩阵的存储顺序为 0,3,1,4,2,5，stride=(2,1)。连续复制保留数值语义，却支付读写、分配和可能的同步成本。不能仅从 transpose 的代码行断言有复制。

概念检查：reshape 总是视图吗？

不是。reshape 可在布局兼容时返回视图，也可复制；view 对可表示的 stride 有约束。应检查实际 stride、存储关系和 profiler，不用函数名代替观测。

2.2　逻辑载荷、底层存储与数值误差

M_logical = Πⱼ shapeⱼ × element_size [byte](2.2)

一个 [8,1024,4096] BF16 张量的逻辑载荷为 8×1024×4096×2=64 MiB。视图的 numel×element_size 是该视图引用的逻辑载荷；多个视图可能重叠，不能把它们简单相加成新分配量。切片还可能保留更大的底层 storage，设备 allocator 的保留量又是另一层。

BF16 和 FP16 都通常占 2 byte，但指数与尾数布局不同，不能因为容量相同就认为误差相同。布局变化的正确性先比较相同 dtype 的值；精度变化另设容差并说明规模、数值范围与参考精度。融合或并行归约改变加法顺序，浮点结果可能不逐位相同。

2.3　主机返回与设备完成是两个事件

主机通常把任务排入设备队列后继续执行。直接在两个主机时间戳之间包住 kernel 调用，可能只测到提交时间。端到端同步 wall time 在测量前后等待设备完成；设备 Event 测量同一 stream 中指定区间。二者都不能自动代表生产服务端到端延迟。

t_wall = t_after_sync − t_before_submit(2.3)

先预热，再同步清掉前序工作，启动主机计时、提交固定工作、同步后结束计时。Event 在同一 stream 上记录起终点，再等待终点就绪。跨 stream、多个设备和 CPU 处理必须单独建立依赖，不把一个 stream 的 Event 当作全部请求耗时。

可能的隐式同步

设备张量的 .item()、打印、搬到 CPU 或主机根据设备值分支，都可能触发等待。是否发生、代价多大，以实际后端和调用栈为准。不要在计时热区逐次打印设备值。

概念检查：同步时间更长就证明设备算得慢吗？

尚不能。它也可能包含之前排队的工作、其他 stream 或拷贝；先固定测量区间并排除前序任务，再比较 Event、wall time 与时间线。

实验使用已有镜像的 PyTorch。CPU 部分可独立运行；CUDA/NPU 部分使用匹配软件栈，脚本不会安装或下载依赖。固定 shape、dtype 和重复次数，比较 contiguous view、转置 view 与显式 contiguous 复制的元数据。

ASCEND_RT_VISIBLE_DEVICES=0 .venv/bin/python labs/lesson02_tensor.py --device npu --output records/l02-910c-run01.json

120 分钟：20 分钟记录环境；25 分钟验证 shape/stride 与数值；45 分钟预热并比较提交时间、同步 wall time，CUDA 另记 Event；30 分钟整理。先预测输出再运行。设备不存在时保留错误，完成 CPU 结果并标记异步部分待实测。

主要结论应为“转置视图是否共享存储、复制在哪一步发生、计时边界包含什么”。不要把这个小矩阵实验当作 vLLM Attention 的性能预测；下一课再建立带宽与工作量模型。
